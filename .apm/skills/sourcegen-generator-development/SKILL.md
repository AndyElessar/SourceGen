# SourceGen Generator Development

Core rules are in `.github/instructions/csharp-source-generator.instructions.md` and apply automatically to generator code. This skill adds the workflow, examples, and references.

## Workflow

1. Find the analogous existing feature and follow its pipeline, model, and emission pattern. If behavior changes, update the spec first (`sourcegen-spec-writing` skill).
2. Implement: pipeline → immutable model → emission → analyzer diagnostics (if needed).
3. Add tests following `.github/instructions/csharp-tunit.instructions.md`.
4. If generated code changes, confirm it is AOT-safe (no reflection-based activation, no runtime `MakeGenericType`) and run the domain's AOT tests.

## Pipeline

```csharp
[Generator]
public sealed class MyGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        var models = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                "MyNamespace.MyAttribute",
                predicate: static (node, _) => node is ClassDeclarationSyntax,
                transform: static (ctx, ct) => MyModel.Create(ctx, ct))
            .Where(static m => m is not null)
            .Collect();

        context.RegisterSourceOutput(models, static (spc, items) => Emit(spc, items));
    }
}
```

- `MyModel.Create` extracts strings, flags, and `ImmutableEquatableArray<T>` — no symbols or syntax nodes.
- Read MSBuild properties via `context.AnalyzerConfigOptionsProvider` (see `IocSourceGenerator.ConfigProviders.cs`) and `.Combine(...)` them, keeping the combined value equatable.

## Emission with SourceWriter

```csharp
var writer = new SourceWriter();
writer.WriteLine("// <auto-generated/>");
writer.WriteLine("#nullable enable");
writer.WriteLine();
writer.WriteLine($"namespace {model.Namespace};");
writer.WriteLine();
writer.WriteLine($"partial class {model.TypeName}");
writer.WriteLine("{");
writer.Indentation++;
// members...
writer.Indentation--;
writer.WriteLine("}");

spc.AddSource($"{model.HintName}.g.cs", writer.ToString());
```

Sort inputs before emitting so the output is deterministic.

## Diagnostics

Descriptors and reporting belong in a `DiagnosticAnalyzer` in the analyzer folder, never in the generator:

```csharp
internal static readonly DiagnosticDescriptor InvalidUsage = new(
    id: "SGIOC0XX",
    title: "Invalid usage",
    messageFormat: "The type '{0}' cannot be used with this attribute",
    category: Constants.Category_Usage,
    DiagnosticSeverity.Error,
    isEnabledByDefault: true);
```

- IDs follow the domain prefix (e.g. `SGIOC`); check the analyzer spec for the next free ID and document new IDs there.
- The generator skips invalid input silently; the analyzer reports it.
