# C# Source Generator Rules

Examples, testing patterns, and references: see the `sourcegen-generator-development` skill.

## Pipeline

- Implement `IIncrementalGenerator`, never `ISourceGenerator`.
- Use `ForAttributeWithMetadataName`; keep syntax predicates cheap and free of semantic-model access.
- Transforms must be pure and deterministic; use `static` lambdas to prevent captures.
- Never let `ISymbol`, `SyntaxNode`, `SemanticModel`, or `Compilation` flow past the transform stage — extract into the data model immediately.
- Pass and honor `CancellationToken` in transforms (`ct.ThrowIfCancellationRequested()` in loops).

## Data Models

- Use `readonly record struct` or `sealed record class` with value equality; use a custom `IEqualityComparer<T>` only when that is not feasible.
- Collections in models: `ImmutableEquatableArray<T>`, `ImmutableEquatableDictionary<TKey, TValue>`, `ImmutableEquatableSet<T>` from `PolyType.Roslyn`.

## Code Emission

- Emit with `PolyType.Roslyn.SourceWriter` (`Indentation++` / `Indentation--` for nesting); avoid string concatenation in hot paths.
- Pass `SourceWriter.WriteLine` a string literal, a constant, or an interpolated string that binds to its `WriteLineInterpolatedStringHandler` overload, so the line is appended without allocating it. Never build the line (or a hole) with an expression that allocates a string:
  - a conditional between interpolated strings (`WriteLine(c ? $"a{x}" : $"b{x}")`) → use `if`/`else`, or a hole that picks a literal (`$"{(c ? "await " : "")}{x}"`);
  - a nested `$"..."`, `+` concatenation, or `string.Concat` inside a hole → inline its text into the outer interpolated string;
  - a local or list of strings created only to be written once → write each line directly;
  - `string.Join` over a fixed set → a constant string.
  `string.Join` of generated fragments, and helpers that format reusable expressions (e.g. `FormatExpression`), are acceptable: `SourceWriter` has no partial-line `Write`.
- Every generated file starts with `// <auto-generated/>`, `#nullable enable annotations` and `#nullable disable warnings`: nullable flow analysis of large generated files dominates their compile time. Tests compile generated files with nullable warnings enabled and fail on any warning.
- Generate `partial` types to augment user code; never replace user-written code.
- Output must be deterministic — stable ordering, no timestamps or GUIDs.

## Diagnostics and Robustness

- Diagnostic descriptors and reporting live in the separate analyzer (`DiagnosticAnalyzer`), never in the generator.
- Invalid input must not crash the generator: skip the invalid item and keep processing valid ones.

## Dependencies

- Generator projects target `netstandard2.0`, keep dependencies minimal, and reference only stable Roslyn packages.
