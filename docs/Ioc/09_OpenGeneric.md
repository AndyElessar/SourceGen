# Open Generic Types

In `Microsoft.Extensions.DependencyInjection`, open generic types can be registered and resolved at runtime.  
However, this involves runtime reflection which can be costly in terms of performance, and does not support nested generic types.  
`SourceGen.Ioc` can automatically discover closed generic types used in constructor/property/method injection or `IServiceProvider` resolution, generating registration code at compile time to eliminate runtime reflection overhead and support nested generic types.

## Basic Open Generic

```csharp
public interface IRepository<T>;

[IocRegister(ServiceLifetime.Scoped, typeof(IRepository<>))]
internal class Repository<T> : IRepository<T>;
```

<details>
<summary>Generated Code</summary>

```csharp
// <auto-generated/>
services.AddScoped(typeof(global::MyNamespace.Repository<>), typeof(global::MyNamespace.Repository<>));
services.AddScoped(typeof(global::MyNamespace.IRepository<>), typeof(global::MyNamespace.Repository<>));
```

</details>

## Auto-Discovery

The generator automatically discovers closed generic types used in:

- Constructor parameters
- Property/field types marked with `[IocInject]` / `[Inject]`
- Parameters of methods marked with `[IocInject]`
- `IServiceProvider` invocations:
  - `GetService(typeof(T))`
  - `GetService<T>()`
  - `GetRequiredService(typeof(T))`
  - `GetRequiredService<T>()`
  - `GetKeyedService(typeof(T), Key)`
  - `GetKeyedService<T>(Key)`
  - `GetRequiredKeyedService(typeof(T), Key)`
  - `GetRequiredKeyedService<T>(Key)`
  - `GetServices(typeof(T))`
  - `GetServices<T>()`
  - `GetKeyedServices(typeof(T), Key)`
  - `GetKeyedServices<T>(Key)`

Closed generic registrations created this way are discovered in turn: when `Outer<string>` is closed from `Outer<T>(IRepo<T> repo)`, its `IRepo<string>` dependency is closed too. The same applies to its injected properties, fields, and method parameters.

An open generic registration is only closed for type arguments that satisfy its implementation's generic constraints: with `Repo<T> : IRepo<T> where T : struct`, `IRepo<int>` is closed as `Repo<int>`, while `IRepo<string>` is resolved like an unregistered service.

A dependency that nests type arguments deeper on every round of a dependency cycle is not closed, because its closed forms never end: `Node<T>(Lazy<INode<List<T>>> next)` closed as `Node<string>` needs `INode<List<string>>`, which needs `INode<List<List<string>>>`, and so on. `INode<List<string>>` is resolved like an unregistered service (at runtime from the open generic registration, which a container with `IntegrateServiceProvider = false` cannot do), and the analyzer reports `SGIOC036` (no `Lazy<T>` or `Func<T>` on the cycle, so the object graph itself is infinite) or `SGIOC037`. Moving type arguments without nesting them, such as `Pair<T, U>(IPair<U, T> next)`, is closed normally.

```csharp
public interface ILogger<T>;

[IocRegister(ServiceTypes = [typeof(ILogger<>)])]
internal class Logger<T> : ILogger<T>;

[IocRegister]
internal class UserService(ILogger<UserService> logger)
{
    // ILogger<UserService> is automatically discovered and registered
}
```

<details>
<summary>Generated Code</summary>

```csharp
// <auto-generated/>
// Open generic registration
services.AddTransient(typeof(global::MyNamespace.Logger<>), typeof(global::MyNamespace.Logger<>));
services.AddTransient(typeof(global::MyNamespace.ILogger<>), typeof(global::MyNamespace.Logger<>));

services.AddTransient<global::MyNamespace.UserService, global::MyNamespace.UserService>();

// Closed generic discovered from UserService constructor
services.AddTransient<global::MyNamespace.Logger<global::MyNamespace.UserService>, global::MyNamespace.Logger<global::MyNamespace.UserService>>();
services.AddTransient<global::MyNamespace.ILogger<global::MyNamespace.UserService>>((global::System.IServiceProvider sp) => sp.GetRequiredService<global::MyNamespace.Logger<global::MyNamespace.UserService>>());
```

</details>

## Nested Generic Types

`SourceGen.Ioc` supports nested open generic service interfaces that `MS.E.DI` cannot resolve at runtime. When the service interface itself contains nested generics (e.g., `IRequestHandler<GenericRequest<T>, List<T>>`), `MS.E.DI` cannot properly map from the open generic registration to the correct closed generic type.

```csharp
public interface IRequest<TSelf, TResponse> where TSelf : IRequest<TSelf, TResponse>;
public interface IRequestHandler<TRequest, TResponse> where TRequest : IRequest<TRequest, TResponse>;

public record GenericRequest<T> : IRequest<GenericRequest<T>, List<T>>;

[IocRegister]
internal class GenericRequestHandler<T> : IRequestHandler<GenericRequest<T>, List<T>>;

public class Entity;

[IocRegister]
internal class ViewModel(IRequestHandler<GenericRequest<Entity>, List<Entity>> handler)
{
    // ...
}
```

<details>
<summary>Generated Code</summary>

```csharp
// <auto-generated/>
// Open generic registration
services.AddTransient(typeof(global::MyNamespace.GenericRequestHandler<>), typeof(global::MyNamespace.GenericRequestHandler<>));

// Discovered nested generic service interface
services.AddTransient<global::MyNamespace.GenericRequestHandler<global::MyNamespace.Entity>, global::MyNamespace.GenericRequestHandler<global::MyNamespace.Entity>>();
services.AddTransient<global::MyNamespace.IRequestHandler<global::MyNamespace.GenericRequest<global::MyNamespace.Entity>, global::System.Collections.Generic.List<global::MyNamespace.Entity>>>((global::System.IServiceProvider sp) => sp.GetRequiredService<global::MyNamespace.GenericRequestHandler<global::MyNamespace.Entity>>());
```

</details>

> [!NOTE]  
> The service interface `IRequestHandler<GenericRequest<Entity>, List<Entity>>` contains nested generic types. `MS.E.DI` cannot resolve this at runtime because it cannot determine how to substitute `T = Entity` into `IRequestHandler<GenericRequest<T>, List<T>>`. `SourceGen.Ioc` handles this through compile-time code generation.

## Manual Discovery with `[IocDiscover]`

For types not directly referenced in code, use `[IocDiscover]` attribute:

### On Method

```csharp
public interface IRequest<TSelf, TResponse> where TSelf : IRequest<TSelf, TResponse>;
public interface IRequestHandler<TRequest, TResponse> where TRequest : IRequest<TRequest, TResponse>;

public record TestRequest<T> : IRequest<TestRequest<T>, List<T>>;

[IocRegister]
internal class TestRequestHandler<T> : IRequestHandler<TestRequest<T>, List<T>>;

internal class Consumer
{
    // Discover closed generic type for registration
    [IocDiscover<IRequestHandler<TestRequest<string>, List<string>>>]
    public void Process() { }
}
```

<details>
<summary>Generated Code</summary>

```csharp
// <auto-generated/>
// Open generic registration
services.AddTransient(typeof(global::MyNamespace.TestRequestHandler<>), typeof(global::MyNamespace.TestRequestHandler<>));

// Discovered from [IocDiscover] attribute
services.AddTransient<global::MyNamespace.TestRequestHandler<string>, global::MyNamespace.TestRequestHandler<string>>();
services.AddTransient<global::MyNamespace.IRequestHandler<global::MyNamespace.TestRequest<string>, global::System.Collections.Generic.List<string>>>((global::System.IServiceProvider sp) => sp.GetRequiredService<global::MyNamespace.TestRequestHandler<string>>());
```

</details>

### On Class

```csharp
[IocDiscover(typeof(IRequestHandler<TestRequest<CustomType>, List<CustomType>>))]
internal class MyClass;
```

### On Assembly

```csharp
[assembly: IocDiscover(typeof(IRequestHandler<TestRequest<Entity>, List<Entity>>))]
```

## With Decorators

Open generic types with decorators also support automatic discovery:

```csharp
[IocRegisterDefaults(
    typeof(IRequestHandler<,>),
    ServiceLifetime.Singleton,
    Decorators = [typeof(LoggingDecorator<,>)])]
public interface IRequestHandler<TRequest, TResponse>;

[IocRegister]
internal class TestHandler<T> : IRequestHandler<TestRequest<T>, List<T>>;

[IocRegister]
internal class ViewModel(IRequestHandler<TestRequest<Entity>, List<Entity>> handler);
```

<details>
<summary>Generated Code</summary>

```csharp
// <auto-generated/>
// Open generic registration
services.AddSingleton(typeof(global::MyNamespace.TestHandler<>), typeof(global::MyNamespace.TestHandler<>));

// ViewModel with discovered dependency
services.AddTransient<global::MyNamespace.ViewModel, global::MyNamespace.ViewModel>();

// Closed generic with decorator chain
services.AddSingleton<global::MyNamespace.TestHandler<global::MyNamespace.Entity>, global::MyNamespace.TestHandler<global::MyNamespace.Entity>>();
services.AddSingleton<global::MyNamespace.IRequestHandler<global::MyNamespace.TestRequest<global::MyNamespace.Entity>, global::System.Collections.Generic.List<global::MyNamespace.Entity>>>((global::System.IServiceProvider sp) =>
{
    var s0 = sp.GetRequiredService<global::MyNamespace.TestHandler<global::MyNamespace.Entity>>();
    var s1 = new global::MyNamespace.LoggingDecorator<global::MyNamespace.TestRequest<global::MyNamespace.Entity>, global::System.Collections.Generic.List<global::MyNamespace.Entity>>(s0);
    return s1;
});
```

</details>

## Diagnostics

|ID|Severity|Description|
|:---|:---|:---|
|SGIOC036|Error|A dependency of an open generic registration nests type arguments deeper on every round of a dependency cycle, and no dependency on the cycle is a `Lazy<T>` or `Func<T>`, so its object graph is infinite. The dependency is not closed at compile time.|
|SGIOC037|Warning|A dependency of an open generic registration nests type arguments deeper on every round of a dependency cycle behind a `Lazy<T>` or `Func<T>`. The dependency is not closed at compile time, so it is resolved at runtime from the open generic registration (not Native AOT safe), or not at all by a container with `IntegrateServiceProvider = false`.|
