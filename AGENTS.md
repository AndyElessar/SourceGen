# SourceGen

C# incremental source generators for compile-time code generation.

## Principles (highest first)

1. **Correctness** — Generated code must be semantically correct and compile-time validated.
2. **AOT compatibility** — All generated code must pass Native AOT publishing without warnings.
3. **Performance** — Generated code must be efficient and avoid unnecessary allocations.
4. **Incremental performance** — Generators must be incremental (`IIncrementalGenerator`) and avoid allocations in hot paths.
5. **Developer experience** — Clear diagnostics, minimal boilerplate, intuitive attribute API.

## Universal Rules

- Use C# 15 syntax — see [csharp.instructions.md](.github/instructions/csharp.instructions.md)
- Read the relevant spec (`**/Spec/*.spec.md`) before implementing or modifying any feature
- Generator and analyzer code follows [csharp-source-generator.instructions.md](.github/instructions/csharp-source-generator.instructions.md) (incremental pipeline, equatable models, `SourceWriter`, `<auto-generated/>` + `#nullable enable`, deterministic output, diagnostics only in analyzers)
- Tests use TUnit on Microsoft.Testing.Platform: `dotnet run --project <test.csproj> [-- --treenode-filter "/*/*/Class/*"]`. Never use the VSTest `--filter` syntax. Domain test commands are in each domain `AGENTS.md`
- If unsure whether an issue is a design decision or a test failure, **ask the user for clarification**
- DO NOT run benchmarks, ask user run them explicitly if needed.

## Mandatory Final Steps

Every task that modifies code **MUST** complete these steps before finishing:

1. **Run Tests** — Run the filtered tests for the changed feature, then the full test project of every changed domain; if generated code changed, also run the domain AOT tests. Fix failures before proceeding.
2. **Review** — Review the full diff against the spec and the user's request, checking spec compliance, generator anti-patterns (symbol capture, mutable models, non-deterministic output), AOT safety, and missing tests or docs. Fix high-severity findings before finishing.

## Agent Customization

- Sources live in `.apm/` (`instructions/`, `skills/`); external dependencies are declared in `apm.yml`. Edit sources there, never the deployed copies, then run `apm install` to redeploy.
- Instructions apply automatically by file path: `.github/instructions/` (Copilot) and `.claude/rules/` (Claude).
- Skills load on demand: `.agents/skills/` and `.claude/skills/`.
- Agents: `.github/agents/` (Copilot) and `.claude/agents/` (Claude).

## Hierarchy

Subdirectory `AGENTS.md` files specialize these rules for their domain. Local rules inherit from this root and may add constraints but not relax them.
